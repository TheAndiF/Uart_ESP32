Uart_Esp32 v0.31 - Validation status
Date: 2026-10-01
Status: In Prüfung

Implemented:
- Added a checkbox on /uart/console: "Heartbeat aktivieren (echo alle 60 s bei UART-Inaktivitaet)".
- Heartbeat is disabled by default for installations without an existing NVS setting.
- Heartbeat enable state is stored in the uartconf NVS namespace under key con_hb.
- Heartbeat runs in firmware and does not depend on an open browser tab.
- Fixed heartbeat interval is 60000 ms.
- Heartbeat payload is exactly `echo` followed by CR (5 bytes).
- Any received UART data resets the inactivity timer.
- All internal UartManager TX paths now use one tracked write helper and reset the inactivity timer on successful writes.
- Heartbeat uses consoleTxReady(), therefore it is suppressed while UART TX is locked/unavailable or while file download, file upload, probe runner, or decoder field-5 replay owns TX.
- Explicit display pause remains independent; it does not disable the heartbeat.
- Existing multiline command blocks, 32768-byte browser scrollback trimming, and selection-resume behavior remain unchanged.
- Console status JSON now exposes heartbeat_enabled, heartbeat_interval_s, and heartbeat_count.
- Added POST /uart/console/heartbeat for enabling/disabling the function.
- Firmware display version updated to v0.31.
- UART_FW_VERSION updated to 0.31.0.

Static checks performed:
- Project root remains Uart_ESP32.
- JavaScript extracted from the UART console page passes `node --check`.
- FW_BUILD_VERSION is v0.31 and UART_FW_VERSION is 0.31.0.
- CONSOLE_HEARTBEAT_INTERVAL_MS is exactly 60000UL.
- Heartbeat payload source is {'e','c','h','o','\r'}.
- Heartbeat scheduler is gated by consoleTxReady().
- NVS load and save operations for con_hb are present.
- The console page contains the new checkbox and /uart/console/heartbeat API endpoint.
- Console status JSON contains heartbeat_enabled.
- UartManager.cpp contains exactly one direct `_serial->write(...)` call, located inside writeSerialTracked(); all prior internal TX call sites use the wrapper.
- src/main.cpp contains no CR or NUL bytes introduced by the change.
- C/C++ brace counts are balanced in src/main.cpp and src/UartManager.cpp.
- v0.31 DOCX was rendered to three PNG pages and all pages were visually checked for clipping, overlap, table defects, and header/footer issues.
- v0.31 PDF was rendered independently to three PNG pages and all pages were visually checked.

Build status:
- PlatformIO is not installed in the execution environment, therefore no new v0.31 firmware.bin was compiled here.
- Any pre-existing .pio build artifacts in the full project package are from an older project state and must not be treated as a v0.31 build.

Recommended hardware/browser test:
1. Compile and flash v0.31 locally with PlatformIO.
2. Open /uart/console with UART running and TX explicitly enabled.
3. Confirm the new heartbeat checkbox is initially off on a fresh NVS state.
4. Enable the heartbeat and close/reload the browser page; confirm the checkbox returns as enabled and the firmware state remains active.
5. Leave UART RX/TX idle for 60 seconds and confirm the ESP32 sends `echo` plus CR exactly once.
6. Confirm the BX3 shell remains active and observe the expected echoed command/blank line/prompt response.
7. Send a normal console command, then confirm the next heartbeat occurs only after another full 60 seconds of UART inactivity.
8. Produce RX traffic without sending anything and confirm each RX activity postpones the heartbeat by 60 seconds.
9. Enable "Anzeige pausieren" for longer than 60 seconds and confirm the heartbeat still occurs while the visible terminal remains paused.
10. Start UART file download, file upload, Probe-Runner, and decoder field-5 replay individually; confirm no heartbeat is injected while each feature owns TX.
11. Stop UART or disable TX and confirm no heartbeat is sent; restore TX and verify the 60-second timer restarts from current activity/start time.
12. Run a long silent program that can read stdin and verify the documented limitation; disable heartbeat for such use cases if heartbeat characters could affect the program.
